You must implement Python automation for resource allocation analysis with GraphQL integration for capacity planning data retrieval through CI/CD pipeline validation and you must format output as structured deliverables and respond with json or markdown depending on the artifact schema requirements.

## Technical Deliverables

1) Resource allocation Implementation Report: structured as a JSON document containing resource allocation requirements sections, capacity planning implementation specifications, validation results with pass/fail status for each resource allocation criterion, and a coverage summary including sample code snippets demonstrating the resource allocation implementation approach; complete when all sections contain non-empty validated content and the overall compliance score equals 100 percent
2) Capacity planning Analysis Document: formatted as markdown including assessment findings sections for capacity planning, quantified risk scores, prioritized capacity planning recommendations with code example references, and remediation fields; complete when every identified capacity planning item has a severity rating and an assigned resolution deadline
3) Load distribution Validation Checklist: delivered as a structured table with load distribution criterion identifier, expected value, actual value, pass condition, and evidence reference for each load distribution item; complete when every row has all five fields populated and no load distribution criterion shows a failing status
4) Resource allocation Quality Dashboard: output format is a YAML configuration including resource allocation metric definition sections, capacity planning threshold values, measurement intervals, alert conditions, and load distribution trend calculations; complete when the schema validates against the documented resource allocation specification and all metrics produce numeric values within defined bounds
5) Capacity planning Evidence Package: structured as a report including the resource allocation executive summary sections, detailed capacity planning findings organized by category, supporting load distribution data fields, and function signatures with implementation evidence; complete when the package contains at least one resource allocation evidence artifact per documented requirement

## Workflow Process

1. Receive and validate the resource allocation request by checking all required fields against the input specification schema using structured resource allocation validation procedures; if the input is invalid then reject with a structured error response listing each failing field and its constraint violation
2. Analyze the validated resource allocation requirements through systematic decomposition to identify scope boundaries, dependencies, prerequisite conditions, and acceptance criteria applying documented evaluation techniques to assess capacity planning compliance
3. Process the capacity planning implementation by executing each documented transformation step in sequence and recording intermediate results with traceability identifiers; when the processing encounters an error condition then execute the fallback procedure by logging the failure context, attempting recovery with default parameters, and if recovery fails then escalate with complete diagnostic information
4. Evaluate load distribution outputs against all defined quality thresholds using quantitative comparison; decision gate: if all thresholds pass then proceed to delivery applying A/B testing validation, if any threshold fails then execute root cause analysis and route to the refinement iteration

6. Deliver the validated capacity planning output package with complete evidence documentation, reproducibility artifacts, and a structured summary confirming all success criteria are satisfied

- Load distribution Compliance Rate: target >= 98% measured as the count of compliant load distribution outputs divided by total load distribution outputs evaluated per weekly batch; pass condition is met when the weekly rate equals or exceeds 98%

- Defect Escape Rate: target <= 2 defects per 1000 processed items measured across all capacity planning deliverables per monthly review cycle; pass condition is met when the monthly defect count divided by items processed multiplied by 1000 remains at or below 2
