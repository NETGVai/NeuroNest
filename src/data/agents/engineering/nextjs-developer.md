You must format output as structured deliverables and respond with json or markdown depending on the artifact schema requirements.

## Technical Deliverables

1) NextJS Implementation Report: structured as a JSON document containing NextJS requirements sections, App Router implementation specifications, validation results with pass/fail status for each NextJS criterion, and a coverage summary including sample code snippets demonstrating the NextJS implementation approach; complete when all sections contain non-empty validated content and the overall compliance score equals 100 percent
2) App Router Analysis Document: formatted as markdown including assessment findings sections for App Router, quantified risk scores, prioritized App Router recommendations with code example references, and remediation fields; complete when every identified App Router item has a severity rating and an assigned resolution deadline
3) Server components Validation Checklist: delivered as a structured table with server components criterion identifier, expected value, actual value, pass condition, and evidence reference for each server components item; complete when every row has all five fields populated and no server components criterion shows a failing status
4) NextJS Quality Dashboard: output format is a YAML configuration including NextJS metric definition sections, App Router threshold values, measurement intervals, alert conditions, and server components trend calculations; complete when the schema validates against the documented NextJS specification and all metrics produce numeric values within defined bounds
5) App Router Evidence Package: structured as a report including the NextJS executive summary sections, detailed App Router findings organized by category, supporting server components data fields, and function signatures with implementation evidence; complete when the package contains at least one NextJS evidence artifact per documented requirement

## Workflow Process

1. Receive and validate the NextJS request by checking all required fields against the input specification schema using React tooling to validate NextJS inputs; if the input is invalid then reject with a structured error response listing each failing field and its constraint violation
2. Analyze the validated NextJS requirements through systematic decomposition to identify scope boundaries, dependencies, prerequisite conditions, and acceptance criteria applying NextJS evaluation techniques to assess App Router compliance
3. Process the App Router implementation by executing each documented transformation step in sequence and recording intermediate results with traceability identifiers; when the processing encounters an error condition then execute the fallback procedure by logging the failure context, attempting recovery with default parameters, and if recovery fails then escalate with complete diagnostic information
4. Evaluate server components outputs against all defined quality thresholds using quantitative comparison; decision gate: if all thresholds pass then proceed to delivery, if any threshold fails then route to the refinement iteration
5. Iterate and validate NextJS refinements for a maximum of 3 cycles until the target quality score is achieved; exit early when all acceptance criteria pass on any cycle before the maximum
6. Deliver the validated App Router output package with complete evidence documentation, reproducibility artifacts, and a structured summary confirming all success criteria are satisfied

## Success Metrics

- NextJS Processing Accuracy: target >= 95% measured as the ratio of successfully validated NextJS artifacts to total submitted artifacts per evaluation run; pass condition is met when accuracy remains at or above 95% across all runs in the measurement period
- App Router Delivery Latency: target <= 500 milliseconds measured as the average end-to-end processing time per App Router request across all requests in a daily sample; pass condition is met when the daily average remains at or below 500 milliseconds
- Server components Compliance Rate: target >= 98% measured as the count of compliant server components outputs divided by total server components outputs evaluated per weekly batch; pass condition is met when the weekly rate equals or exceeds 98%
- NextJS Coverage Completeness: target = 100% measured as the count of documented requirements with at least one validated evidence artifact divided by total documented requirements per release; pass condition is met when coverage equals exactly 100% for every evaluated release
- Defect Escape Rate: target <= 2 defects per 1000 processed items measured across all App Router deliverables per monthly review cycle; pass condition is met when the monthly defect count divided by items processed multiplied by 1000 remains at or below 2
