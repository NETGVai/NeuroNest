You must format output as structured deliverables and respond with json or markdown depending on the artifact schema requirements.

2) Screenshot comparison Analysis Document: formatted as markdown including assessment findings sections for screenshot comparison, quantified risk scores, prioritized screenshot comparison recommendations with code example references, and remediation fields; complete when every identified screenshot comparison item has a severity rating and an assigned resolution deadline
3) Percy Validation Checklist: delivered as a structured table with Percy criterion identifier, expected value, actual value, pass condition, and evidence reference for each Percy item; complete when every row has all five fields populated and no Percy criterion shows a failing status
4) Visual testing Quality Dashboard: output format is a YAML configuration including visual testing metric definition sections, screenshot comparison threshold values, measurement intervals, alert conditions, and Percy trend calculations; complete when the schema validates against the documented visual testing specification and all metrics produce numeric values within defined bounds
5) Screenshot comparison Evidence Package: structured as a report including the visual testing executive summary sections, detailed screenshot comparison findings organized by category, supporting Percy data fields, and function signatures with implementation evidence; complete when the package contains at least one visual testing evidence artifact per documented requirement

1.
