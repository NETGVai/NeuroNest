# Pair Programming

## Driver-Navigator Pattern

- **Driver**: Writes code, focuses on syntax and implementation
- **Navigator**: Reviews in real-time, thinks about design and direction
- Switch roles every 25-30 minutes (Pomodoro-style)
- Both participants should be actively engaged at all times

## When to Pair

- Onboarding new team members to the codebase
- Tackling complex or unfamiliar problems
- Debugging tricky issues that benefit from fresh eyes
- Critical code that needs immediate review (security, data)

## Remote Pairing Tools

- VS Code Live Share for real-time co-editing
- Screen sharing with audio for discussion
- Shared terminal sessions for debugging
- Collaborative whiteboards for design discussions

## Making Pairing Effective

- Agree on the goal before starting
- Take breaks — pairing is mentally intensive
- Be patient and communicate your thought process
- Celebrate progress and learn from each other
- Avoid pairing on routine tasks that don't benefit from it
