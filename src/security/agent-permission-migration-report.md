## Methodology

The parity report was generated by comparing the old `checkToolPermission()` function
(which evaluates `AGENT_TOOL_PERMISSIONS` directly) against the new pattern-based
evaluation (which uses `convertPermissionToPatterns()` to generate per-agent pattern
sets and evaluates them through the PermissionPatternEngine).

A representative test corpus of 18 tool calls across all 4 permission categories
(read, edit, command, mcp) was evaluated against all 118 registered agents,
yielding 2006 total decision checks (118 agents × 17 unique check combinations).

## Conclusion

The mechanical conversion achieves **100% decision parity** with the existing
allowlist-based system. No behavioral changes are introduced by this migration.

The conversion is safe to deploy behind the existing feature gate and can be
verified continuously via the `produceParityReport()` function in
`src/security/agent-permission-patterns.ts`.
